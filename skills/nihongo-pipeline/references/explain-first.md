# 説明してから短くする

okazuki「AI の謎な説明文を直すスキル」(https://zenn.dev/microsoft/articles/explain-before-shorten) の考え方をもとに、この工程用に書き直した手順書である。元のスキル文書を使いたいときは、設定の explain_skill にそのファイルのパスを書く。

短くしすぎて意味が1つに決まらない見出し・箇条・説明文を、いったん口で説明する形に広げてから、意味を保って短くする。語を削るだけで直そうとしない。扱う話題を絞って短くする。

## 手順

1. その箇所で読み手に分かってほしいことを1文で書く。仕組みを知る、違いを知る、手順を実行する、のどれなのかを決める。前後を読んでも決まらなければ、報告の「書き手に確かめたい点」に書く。
2. 読み手が隣にいるつもりで、口で説明する文を組み立てる。字数は気にしない。何が・どうなるか、なぜか、どんな場合か、を必要な範囲で書く。「分離」「管理」「対応」「保証」のような語を使うなら、実際に何が起きるかも書く。
3. 違う話を分ける。仕組み・条件・例外・注意は別の文にする。条件は、それがかかる文や表のセルの近くに置く。その場所に要らない補足は外す。外した補足は報告に書く。
4. 意味を保って短くする。重なり、前置き、回りくどい修飾を削る。誰が・何を・どうするか、因果、比べる相手、大事な条件は残す。その場で作った言い方より、意味がそのまま伝わる言い方を選ぶ。削っても収まらなければ、扱う話題を減らす。
5. 読み手にしてほしいことは、できるだけ肯定の形で書く (「設定を忘れない」より「設定を確かめる」)。禁止・危険・例外・できないことは否定の形のまま書く。形を変えて、条件や強さや範囲が変わるなら元の形を保つ。
6. 短くした文だけを読んで、何の話で何が起きるかが分かるかを確かめる。隣の文と続けて読み、話題が急に変わっていないかも見る。分からなければ、語の置き換えを繰り返さず手順2に戻る。

## 書き換えの例

| 短くしすぎた表現 | 口で説明できる表現 |
|---|---|
| 受付と完了確認を分離する | 処理の終わりを待たずに受付済みと返し、結果はあとから問い合わせてもらう |
| 上限数は到達保証ではない | 表の台数は上限で、割り当ての制約によってはそこまで増やせない場合がある |
