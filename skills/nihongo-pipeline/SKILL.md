# nihongo-pipeline

日本語の文書を、工程ごとに担当を1つに絞って仕上げる。各工程は新しいサブエージェントが、その工程のスキル文書だけを読んで行う。複数の文章術スキルを1つの文脈に読み込むと、指示が食い違い、長い規則の一部が読み落とされるためである。

工程の順序・受け渡すファイル・通過の条件・差し戻しの回数は、このスキルの `scripts/jpipe.py` (以下 jpipe) が決める。あなたは jpipe が表示する「操作」を1つずつ実行する。工程を飛ばす、順序を変える、自分で本文を直す、の3つはしない。

## 始める前に

`python3 <このスキルのフォルダ>/scripts/jpipe.py doctor` を一度実行し、部品がそろっているかを見る。yomiyasu が見つからなければ `jpipe setup` を実行する。別のモデル (agy / gemini / codex) が見つからなくても、判定の工程を省いて進められる。

## 経路を選ぶ

| 依頼 | 経路 | 始め方 |
|---|---|---|
| 新しく書く (記事・レポート・提案書・議事録など) | new | 会話と資料から事実のメモを作り、`init --route new --material facts.md` |
| 既にある原稿を直す | revise | 原稿を .md にして `init --route revise --src draft.md` |
| スライド・箇条書き・短い説明文の文言 | explain | 文言を .md に抜き出して `init --route explain --src text.md` |
| 工程に通すほどでない短い文書 | (なし) | 書いたあと `certify file.md` |

事実のメモには、利用者が言ったことと、確かめた資料の内容だけを書く。推測は書かない。主メッセージ (読み手に伝えたいことの1文) を利用者が言っていれば、メモの先頭に書く。

`init` の主なオプション: `--doc-type` (article / proposal / minutes / mail / slides / manual / paper など)、`--reader` (expert / informed / general)、`--style` (desu / dearu / keep)、`--purpose "読み手と目的を1文で"`、`--draft external` (下書きを別のモデルに任せる)、`--explain` (new と revise に説明の組み立てを足す)、`--no-review`。

## 進め方

1. `init` の出力の最後に、次の工程の「操作」が出る。それを実行する。
2. サブエージェントの工程は、`Agent(subagent_type="jp-stage", prompt="brief: <brief のパス>")` で任せる。プラグインとして入れた環境では subagent_type が `nihongo-pipeline:jp-stage` になる。どちらもなければ、汎用のサブエージェントに「この brief を読み、その指示だけに従う」と渡す。brief の中身を自分で書き換えない。
3. サブエージェントが終わったら `jpipe done`。足りないものがあれば jpipe が理由を出すので、同じ brief でもう一度任せる。
4. スクリプトの工程は `jpipe run`。別のモデルを呼ぶ工程 (review・draft_external) は数分〜10分かかるので、バックグラウンドで実行して終わりの通知を待つ。
5. 検査か判定で指摘が出ると、jpipe が修正の工程を1回だけ差し込む。2回目の検査のあとは差し戻さない。
6. 最後の confirm で、jpipe が「書き手に確かめたい点」と残った指摘を出す。確かめたい点があれば利用者に聞く。答えで本文が変わるなら、書き出したあとに revise でもう一度通す。
7. `jpipe finish --out <書き出し先>` で最終稿を書き出す。出力された工程の記録の要点 (省いた工程、残した指摘、照合の結果) を利用者に伝える。

途中で文脈が切れたら `jpipe status` で今の工程が分かる。

## hook との関係

このプラグインの hook は、日本語の依頼に返答の決まりを注入し、ターン中に書いた日本語の文書が検査を通っていなければ、返答を終える前に止める。止められたら、その文書に `certify` を実行するか、工程に通す。検査が要らない中間ファイルは `certify <file> --accept "理由"` で理由を残す。利用者が依頼に `#nopipe` を書いたターンは、hook は何もしない。

## 別のモデルがない環境

agy・gemini・codex のどれもない環境、または呼び出しに失敗したときは、判定の工程を「省いた」と記録して次へ進む。`--draft external` は Claude の下書きに切り替える。どちらも工程の記録に残るので、利用者への報告に含める。
